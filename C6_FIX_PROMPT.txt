INDEPENDENT AUDIT RESULT

AUDIT RESULT: FAIL - CHANGES REQUIRED

The implementation is strong on authorization, tenant isolation, DTO safety, bounded queries, C4/C5 integration, and regression coverage. The blocker is that the Content destination is not truly conditional.

BLOCKER

The shell hides Content navigation when hasPortalContent is false, but /portal/content still renders after ordinary portal authentication. This violates the binding C6 conditional-destination contract.

Observed bad scenarios:

1. A Client with no eligible C6 Content can directly visit /portal/content and receives a 200 page with an empty global Content module.
2. A Client whose only readable Content is Published more than 30 days ago can currently make hasPortalContent true even though current, action, and published C6 views all return zero discoverable items. The destination appears but contains nothing discoverable.

Binding contract direction:

- docs/phases/C6.md requires Content to be a meaningful conditional destination.
- Do not show an empty global Content module merely because the workspace or Client has Social internally.
- Navigation eligibility and direct route eligibility must agree.
- Hidden/unauthorized rows must not influence destination eligibility.
- Per-view empty states are still valid for a Client whose Content destination is eligible overall.

REQUIRED FIX

Make the smallest coherent correction:

1. Define one canonical C6 Content-destination eligibility predicate/projection representing the union of Content actually discoverable through the C6 portal views.
   - Eligible non-Published/current work that can appear in the C6 current/action views.
   - Published Content only when it is inside the C6 recent-publication window currently defined by the phase implementation, which is 30 days.
   - Do not count hidden, unauthorized, wrong-client, invalid-parent/service, or otherwise non-discoverable rows.
   - Do not create a duplicate mutable flag or schema field.

2. Reuse that same destination eligibility for conditional portal navigation.
   - Do not let hasPortalContent use a broader definition than the Content pages themselves.
   - A Client with only Published Content older than the recent-results window must not get the Content destination solely because that old row exists.

3. Gate direct access to /portal/content using the same current server-side eligibility.
   - If the Client is authenticated for the portal but the Content destination is ineligible, redirect to /portal using the repository's established server-side routing pattern.
   - Do not rely on hidden navigation or client-side state.
   - Preserve normal authorization behavior for unauthenticated/invalid portal sessions.

4. Preserve per-view empty states when the Content destination is eligible overall.
   Example: a Client may have discoverable recent Published Content while the Current view itself is empty. That per-view empty state is valid and should remain.

5. Fix the browser acceptance harness.
   - Remove/replace any assertion that currently treats direct access to an irrelevant empty Content module as correct.
   - Prove an ineligible Client is redirected away from /portal/content.
   - Prove a Client with only a Published item older than the 30-day window has no Content nav and cannot remain on /portal/content.
   - Keep existing Social-only, multi-service, current, action-required, recording, approval, file, recent-publication, responsive, accessibility, revocation, and C5 regression coverage green.

6. Add focused automated regressions for at least:
   - no eligible Content: nav absent and direct /portal/content gated/redirected
   - only old Published Content outside the recent-results window: nav absent and direct route gated/redirected
   - eligible current/upcoming Content: nav present and route accessible
   - eligible recent Published Content with no current work: destination still eligible; per-view empty state remains valid
   - hidden/foreign rows do not make destination eligible

7. Correct documentation that conflicts with the binding contract.
   - Remove/rewrite any docs/DOMAIN_MODEL.md or docs/BUILD_STATE.md statement claiming direct empty Content access is useful/intentional.
   - Record the corrected destination eligibility semantics accurately.
