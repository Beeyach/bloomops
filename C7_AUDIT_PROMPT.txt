PRIMARY AUDIT GOAL
Determine whether PR #28 safely closes Release C. C7 is hardening only. It must not introduce new product features or weaken any existing C1-C6 guarantees.

AUDIT AREAS

1. Exact scope and release-contract compliance
- Confirm C7 implements only hardening/fixes and integrated proof.
- Confirm no Release D work, new product features, schema expansion, dependency changes, provider work, notification system, publishing integration, Ads/Systems/Pages/Finance work or unrelated refactor.
- Check all 11 changed paths and confirm there are no hidden/unlisted product changes.

2. Tenant isolation and authorization
Attack direct API and server-page access, not only UI visibility.
Verify:
- no cross-workspace Content/approval/File/recording/platform/calendar/portal access
- no cross-Client access inside one workspace
- PM/Team access remains assignment-based
- Department, owner, Project, Action and unrelated Service relationships never grant Content authority
- current membership, role, workspace, Client contact, Content visibility and optional Social service truth are rechecked
- issued sessions lose access immediately after revocation/reassignment
- authorization order does not leak record existence or internal state

3. Content lifecycle legality
Recheck the full C2 pipeline under C4-C6 integrations:
- ordinary edits cannot bypass stage transitions
- recording/internal-review/client-approval flags compose correctly
- Published remains terminal
- recording/approval endpoints cannot create illegal stage changes
- stage/context/activity do not become competing truth
- stale/concurrent operations have one canonical winner

4. Approval and revision integrity
Recheck C5 invariants in the integrated Release C story:
- immutable review snapshots
- append-only rounds
- exactly one Requested round
- stale approval pages cannot resolve the wrong round
- approve / changes requested / withdraw / edit / stage races
- duplicate retries converge
- failed late writes roll back coherently
- round 1 remains preserved after round 2

5. Files and recordings
Recheck C4/C6 File boundaries:
- C4 remains sole File/R2 authority
- generic/internal assets never become Client-visible
- only authorized Ready recording files download
- upload/retry cannot cross Content, Client or workspace
- stage/contact/visibility/service/membership revocation removes metadata/download authority immediately
- post-R2 authorization recheck is actually effective, including the new in-flight revocation story

6. Calendar, platform and date correctness
Verify:
- same-workspace/same-Content platform relationships
- deterministic ordering and null handling
- 30-day recent-publication boundaries and future timestamps
- hidden/foreign rows cannot influence counts, pagination or destination eligibility
- no duplicate calendar/schedule state

7. Client portal safety
Verify C6 still guarantees:
- exact allowlisted DTOs
- no script/caption/hook/CTA/pillar/internal owner or assignment/CAS/revision/activity/stage-context/service/member/workspace/storage leakage
- C5 Requested snapshot is the only route to approval copy
- conditional Content navigation remains correct
- direct /portal/content gating matches navigation
- no-client and disabled-client-access behavior remains unchanged

8. C7-specific fixes
Independently verify the Social list/calendar error-page heading correction.
Confirm:
- invalid filters retain normal page headings
- recovery controls remain correct
- authorization order is preserved
- tests fail against the pre-fix behavior if practical to prove the regression is meaningful

- multiple Clients
