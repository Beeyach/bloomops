# Pages recovery

Local built-Worker evidence using isolated synthetic records, 14 September 2026. This slice is not merged or deployed. [Desktop conflict review](page-recovery-1440.png), [phone](page-recovery-390.png), [narrow phone](page-recovery-320.png), and [keyboard focus](page-keyboard-focus.png).

The existing internal and client PageEditor keeps ordinary serial autosave and the mature RichEditor. Recovery offers metadata first, then explicitly checks the initiating user, workspace and current direct/inherited edit grant before revealing document input. Recovered drafts wait for deliberate save. The exact outstanding save attempt survives reload: a committed-but-lost reply is confirmed without another write, while later input remains available. Another writer's revision requires conflict review or deliberate use of the latest saved version. Download also checks current edit authority.

Modern copies are separate per user/workspace/page/writer, bounded to ten, seven days and 8MiB encoded each. Browser quota can be lower; storage errors retain mounted input and warn the user rather than claim persistence. Original tab-only copies remain available through explicit recovery; because their old format has no creation timestamp, their seven-day clock starts at first observation and does not reset on reload. A verified source is conditionally removed only after save/use-saved confirmation; a newer source and independent copies survive.

Logout clears modern copies and invalidates active editors. A persistent logout marker retires inactive tabs' old sessionStorage copies when they next open an editor; active tabs receive the shared event/BroadcastChannel signal. Workspace switching keeps the original workspace's copy. Account replacement remounts the editor; page departure invalidates it, so returning from a retained document requires reload and checked recovery. Browser storage removal and cross-device synchronization are outside this feature.
