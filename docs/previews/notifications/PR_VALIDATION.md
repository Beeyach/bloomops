`.github/workflows/pr-validation.yml` runs on main-targeting PR opened, synchronize, reopened and ready_for_review events, including drafts. It checks out `github.sha`, the event's generated merge candidate, and exports base, feature, merge and actual checkout identities. It uses Ubuntu24.04, Node22.23.2, each checkout's `npm ci`, UTC, read-only contents permission, no persisted Git credentials, no secrets/environment, and verified official action commit pins. Concurrency cancels superseded runs; artifacts expire after five days. No push trigger, deployment or shared resource access is added. Existing main deployment workflows remain unchanged.

The feature job runs the exact notification22 and combined273 Node commands from [N2](../../phases/N2.md), native disposable D1, and the zero verifier with mandatory `--local`. It builds before running the unchanged full notification browser suite (`--skip-performance`) and focused preferences suite (`--preferences-only`). Playwright1.58.2/Chromium live in isolated runner temporary paths. Each browser invocation creates/disposes its own local Worker and synthetic D1/R2. The existing build identity, process, version, served-asset and unchanged-artifact checks remain enabled. No performance acceptance is inferred.

The independent full-suite job runs `npm test` and keeps its real exit status. After candidate failure, it checks out the exact event base into a separate directory, runs its own `npm ci` and `npm test` on the same runner/runtime/UTC clock, and exports individual TAP diagnostics. `.github/scripts/pr-validation.py` records timestamps, revision, runtime, lockfile hash, command, exit code, TAP counts and failures. Its comparison removes timing/location/stack details only; actual/expected/error/operator remain. Matching diagnostics are evidence for inspection, never a waiver or green check. A UTC-date crossing marks comparison conditions unresolved; reviewers must also inspect date-sensitive fixture cutoffs. Base-only failures are retained.

Only sanitized command logs, receipts and existing synthetic browser evidence are uploaded, not checkouts, environment files, dependencies or build bundles. `if: always()` uploads available evidence on failure. An installation/account restriction can leave checks unexecuted and must be reported as such. Feature validation can pass while the full-suite job remains failed; the workflow must not be described as green in that case.

No existing test assertions or application/migration/dependency files changed. Remote run URLs/results are recorded on PR78 after execution rather than predicted here.
