## Integration

Controlled GHL/Kajabi metadata selects the canonical defaults, without accepting
caller-provided template definitions or inferring platform from Service names.
Share provisioning and configure implementation while keeping existing GHL
exports and endpoint contracts. Each platform's explicit setup cannot replace
the other's binding. Enabling checks the exact active, sole published default at
the final write/no-op; disable remains identity-only and never repairs history.

Expose a narrow Kajabi Settings page and protected setup endpoint alongside GHL,
reusing the existing form/dialog. Project options identify the trusted blueprint
for correct GHL/Kajabi labels; both use the same options/preview/generate routes.
Keep the existing bounded, workspace/membership/Project-scoped storage key and
packet shape to preserve outstanding GHL requests. Recovery copy may be generic
when the original blueprint cannot be determined from current eligible options.
No mount-time generation or silent fallback to another blueprint.
