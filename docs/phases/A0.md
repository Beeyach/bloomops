# A0 — Create BloomOps Safely

## Objective

Create an independent BloomOps codebase from a clean snapshot of the tracked `origin/main` contents of `Beeyach/bloomtrack-pro`.

Do not begin infrastructure migration or product changes.

## Required Result

- target repo: `Beeyach/bloomops`
- visibility: private
- default branch: main
- source: latest fetched `origin/main` of `Beeyach/bloomtrack-pro`
- fresh Git history
- exact source commit SHA recorded in BloomOps
- `CLAUDE.md` preserved
- `docs/` planning documents preserved
- inherited app installs, tests, and builds if the source snapshot supports them

## Critical Safety Rules

Do not:

- modify `bloomtrack-pro`
- push to `bloomtrack-pro`
- copy untracked/uncommitted local files from `bloomtrack-pro`
- alter Leadsthatbloom Cloudflare resources
- touch the Leadsthatbloom production D1
- touch Leadsthatbloom R2
- change DNS
- begin A1

The tracked `origin/main` snapshot is the source of truth.

## Important Existing BloomOps State

The target repository may already contain planning files created before the source snapshot is imported.

Do not delete them.

The source snapshot import must preserve:

- `CLAUDE.md`
- `docs/INDEX.md`
- `docs/BUILD_STATE.md`
- `docs/PRODUCT_SPEC.md`
- `docs/DOMAIN_MODEL.md`
- `docs/RELEASE_A.md`
- `docs/ROADMAP.md`
- `docs/phases/`

If a source file conflicts with one of these paths, preserve the BloomOps planning file and document the conflict.

## Preserve the Notion-Style Pages System

The source snapshot contains mature Pages/editor code that BloomOps intends to reuse later. A0 must import it unchanged as part of the source snapshot and verify these anchors still exist:

- `components/RichEditor.jsx`
- `components/PageView.jsx`
- `components/BlockInsertMenu.jsx`
- `components/DatabaseViewNode.jsx`
- `components/PublicReader.jsx`
- `lib/editor-extensions.mjs`
- `lib/page-tree.mjs`
- `lib/page-share.mjs`

Do not adapt, restyle, or rewrite these files during A0. See `docs/PAGES_SYSTEM.md` for the later migration strategy.

## Verification

Before action:

- inspect pwd
- inspect git status
- inspect branch
- inspect remotes
- fetch source origin
- record exact source SHA
- confirm target repository identity and privacy

After import:

- verify BloomOps origin points only to `Beeyach/bloomops`
- verify fresh Git history
- verify source SHA documented
- install with the repository lockfile
- run existing tests
- run existing production build
- inspect git status
- update `docs/BUILD_STATE.md`

If an inherited test/build fails, determine whether the failure exists in the source snapshot. Do not turn A0 into an unrelated repair phase.

## Exit Criteria

A0 is complete only when:

- BloomOps has the source snapshot
- BloomOps planning docs remain intact
- source SHA is recorded
- test/build outcome is recorded
- Leadsthatbloom remained untouched
- no A1 work was performed

## Stop Boundary

Stop after A0.
