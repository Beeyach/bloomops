### Read and permission contract

- A dedicated `/prospecting/import` page, reached by “Review source” on the list, requires the selected active Prospecting workspace and Owner/Admin role. No source is selected automatically.
- Source choices are the same signed-in identity's active Owner/Admin memberships in active operational workspaces in the current database. Explicit selection grants no new membership; source IDs are never authority by themselves. The original inherited app adapter remains closed from fresh Prospecting workspaces.
- Each source-data query must recheck both the destination's exact issued membership and the source's active same-user Owner/Admin membership. Revoke either, deactivate either workspace, change either role or guess a foreign ID: return unavailable without exposing record existence.
- Read inherited source rows and activity directly without calling legacy reconciliation/read helpers that write counters, jobs or history. Drizzle remains the database entry point. Never read settings, mailbox credentials, message bodies, voice assets or report bodies into this preview.
- This reads only legacy tables in the currently bound database. It is not a connector to the separate original LTB deployment. Empty source inventory stays empty; no remote source is silently connected or copied.
- Bound each page to 50 records plus one overflow sentinel, ordered by immutable source ID with a keyset cursor. Return page-level counts and an as-of time, not invented global totals or a snapshot guarantee. Reload re-evaluates activity. Missing required source schema fails closed, never counts as empty history.

### Classification contract

Use three outcomes with readable reasons: **No recorded work**, **Already worked**, **Needs review**. “No recorded work” is evidence for a later export decision, not a guarantee of never having been contacted and never an outreach permission.

- Positive stop/contact/conversion evidence wins regardless of a `New` label or zero cached counters: sent/reply dates/counters, opt-out/do-not-contact, client/proposal/call state, message/event/relationship ledgers, send attempts, client linkage and deferred/accepted states exclude the row.
- Prior drafts, audits, qualification, contact research, recorded jobs and outreach packages also mean the record is not untouched. Never copy those fields as raw identity data.
- An unexplained stage/state, malformed counters or activity, duplicate source email, unstructured notes, edited timestamps without corroborating history, or invalid raw identity fields puts the row aside. Do not parse prose into a clean bill of health or rewrite the source to make it eligible.
- Source deletion is exclusion. Duplicate email checks include deleted rows so soft deletion cannot hide contact history. Email matches in unmatched reply inventory are ambiguity even if the current prospect ID has no message.
- Only business/person names, website, public email, niche, country and source label are displayed as raw candidate fields. Full reports, drafts, message contents, old qualification and schedules never enter the DTO. Unknown platform/timezone/services are not invented from a source label or prose.
- Reasons are typed summaries of evidence; no sensitive event contents are returned. Page counts reconcile to the displayed records. There is no import/export/send action in this slice.
