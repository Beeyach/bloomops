## Release C Invariants To Prove

C7 must prove the integrated system preserves these invariants under direct API use, stale sessions, retries and concurrent operations.

### Tenant and scope isolation

- no internal or Client user can read or mutate another workspace's Content, approvals, Files, recordings, platforms, calendar facts or portal projections
- PM/Team scope remains assignment-based exactly as the earlier phase contracts define
- Department, owner, Project, Action and unrelated relationships never grant accidental Content access
- current membership, role, workspace, Client contact, Client visibility and optional canonical Social service truth is rechecked on each sensitive operation
- revocation takes effect immediately on the next request even for previously issued sessions

### Content lifecycle legality

- all C2 conditional stage transitions remain legal and cannot be bypassed through ordinary edits or later C4-C6 endpoints
- recording-required, internal-review-required and Client-approval-required branches behave correctly in every applicable combination
- Published remains terminal unless earlier contracts explicitly define otherwise
- current stage/context and activity history never become competing sources of truth

### Approval and revision integrity

- prior review snapshots and prior rounds remain immutable and append-only
- exactly one Requested round can exist per Content Item
- stale approval pages cannot resolve the wrong round
- approve, changes-requested, withdraw, edit and competing stage transitions have one canonical winner under concurrency
- identical retries converge without duplicate round/revision/activity/stage facts
- failed late writes roll back coherently

### Files and recordings

- C4 remains the sole Content File/R2 authority
- hidden/internal assets never become Client-visible through C6
- only currently eligible recording Files and Ready downloads behave as earlier contracts allow
- upload retry/recovery cannot cross Content, Client or workspace boundaries
- revoking Content/File/recording eligibility removes metadata and download authority immediately
- post-R2 authorization checks remain effective

### Calendar, platforms and dates

- platform associations remain canonical and same-Content/same-workspace
- date ordering, null handling, inclusive/exclusive boundaries and published/recent windows are deterministic
- calendar and portal views never maintain duplicate schedule state
- hidden/foreign rows cannot influence counts, ordering, page boundaries or overflow

### Client portal safety

- general Content DTOs remain exact allowlists
- C5 review snapshots remain the only route to approval copy when specifically Requested
- no scripts, captions, hooks, CTA, pillar, internal owner/assignment, CAS/revision, activity, stage context, service/member/workspace ids, storage internals or hidden counts leak through C6
- Content navigation remains conditional on discoverable Content
- direct `/portal/content` access is gated consistently with navigation
- no-client and disabled-client-access behavior remains unchanged

## Adversarial Test Direction

Add or strengthen tests only where they prove a real release invariant or expose an actual gap.

At minimum, attack:

- cross-workspace ids
- cross-Client ids inside one workspace
- revoked Client contact/membership/workspace/visibility/service relationships
- stale PM/Team assignment after an issued session
- direct API requests that bypass UI
- malformed and boundary pagination/date inputs
- hidden rows around page boundaries
- races between Content edits and stage changes
- races between approval response/withdraw/edit
- duplicate retries after response loss
- recording/File retry against changed parent authority
- download authorization after eligibility revocation
- recent-published 30-day boundaries and future timestamps
- portal destination eligibility with only hidden, old, foreign or future Published Content
- long text/filenames and narrow viewports
- keyboard focus/trap/restoration where dialogs exist
- touch targets and reduced motion

If existing tests already prove a case convincingly, do not duplicate them merely to increase counts.

When C7 discovers a defect:

1. reproduce it with a focused test or harness case where practical

3. make the smallest correct fix
4. prove the fix

6. document the change precisely

Do not manufacture fixes when no defect exists.
