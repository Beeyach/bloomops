# A11 — Release A Hardening

## Objective

Add no new product features.

Attack Release A for security, lifecycle, isolation, retry, and usability failures.

Read:

- `docs/RELEASE_A.md`
- `docs/DOMAIN_MODEL.md`

## Required Security Scenarios

- Client A requests Client B resource
- Team Member requests unassigned Client resource
- Social-scoped contractor requests GHL-scoped resource
- suspended member uses an existing session
- client attempts internal route/API
- user manually edits resource IDs in URL

All must fail safely.

## Required Data/Isolation Scenarios

- staging cannot write production data
- workspace boundaries are enforced
- client portal APIs omit internal/restricted fields
- template change after activation does not mutate existing onboarding

## Required Lifecycle Scenarios

- activation retry does not duplicate onboarding
- invitation resend invalidates old token
- required item completion updates progress correctly
- waived required item leaves audit trail
- onboarding completion transitions correctly
- incomplete activation prerequisites block clearly

## External Failure Scenarios

- transactional email failure does not corrupt activation
- retry is safe
- partial external failure leaves understandable recoverable state

## Browser Verification

Cover critical flows on:

- desktop
- mobile

At minimum verify the two Release A acceptance stories in `docs/RELEASE_A.md`.

## Exit Criteria

Release A is complete only when:

- critical happy paths pass
- critical denied paths pass
- environment isolation is proven
- release acceptance stories pass
- build/test suite passes
- BUILD_STATE records Release A as complete with verification evidence

## Scope Boundary

No Release B features in A11.
