# A8 — Onboarding Template Engine

## Objective

Build the data-generation engine before building a polished onboarding portal.

Read `docs/DOMAIN_MODEL.md`.

## Initial Template Categories

Support initial onboarding blueprints for:

- Common
- Social
- Ads
- GHL
- Kajabi

## Versioning

Templates are versioned or snapshot immutable definitions.

Generated onboarding must not change when the master template changes later.

## Stable Logical Keys

Deduplicate generated requirements by stable logical key, not visible label.

Examples:

- agreement
- brand_assets
- kickoff_booking
- instagram_access
- meta_business_access
- ghl_access
- kajabi_access
- course_videos

Visible labels may evolve without changing logical identity.

## Merge Behavior

If Client buys Social + Ads and both require Meta access, generate one client-facing Meta access requirement.

The generated item may associate with multiple service engagements internally.

Preserve:

- required/optional
- responsible party
- instructions
- verification requirement
- service relationships
- logical key

## Runtime Data

Generated onboarding becomes relational runtime records.

Do not keep active client onboarding only as opaque template JSON.

## Verification

Test:

- version snapshots
- template edits do not mutate generated onboarding
- duplicate logical requirements merge
- non-duplicates remain separate
- required/optional semantics preserved
- responsible party preserved
- service associations preserved
