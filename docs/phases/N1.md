## N1A — Retry failed sheet saves

The first bounded slice preserves reviewed values after a failed or partially successful sheet save. Keep failed fields and their original comparison values in the mounted review, identify each error beside its field, and offer an explicit retry. Confirm already-applied values after a lost response without writing again. Recheck current profile/revision on every retry and refuse to overwrite a newer field. Preserve undo receipts for confirmed successes across partial retries. Undo and save status must describe the action accurately.

Pending previews require an explicit discard before another edit or sheet query/view replaces them. Ordinary link navigation and browser reload warn about unsaved values; this slice does not claim durable recovery after accepting a leave prompt, closing a crashed browser or losing the component. No draft is written into browser storage and no automatic retry is introduced. Full recovery across navigation/session boundaries, including client-side history navigation, remains N1B.

Acceptance: actual built-Worker checks with synthetic isolated records cover offline/503 failure, mixed success, delayed saves and double submission, retry, committed-but-lost responses, concurrent edits, denied access, undo retention, discard guards, desktop/mobile layouts and no provider egress. Existing focused sheet tests and Worker build must pass. Compare unrelated route bundles and request counts with the accepted build; do not infer a production speed improvement. Apply the configured selective independent review policy.

No migration, server-side authority change, deployment or PR64 merge is required for N1A. Record local acceptance separately from staging. Later N1 work covers broader save/recovery and bounded permission-aware global search.

## N1B — Browser recovery for sheet drafts

Use a separate worktree/branch `feat/n1b-sheet-drafts`, preserving PR64/65 and staging. Retain the typed cell or pending reviewed fields in browser-local storage, scoped to the original user/workspace. Each mounted sheet writes its own draft ID so another tab cannot overwrite its copy. Keep at most ten copies per scope for seven days and cap each at200 fields/256KiB; report unavailable/full storage without pretending the copy is safe.

On a later visit, offer recovery without rendering stored field values first. An explicit read-only, bounded server check must confirm current Owner/Admin prospecting access, matching user/workspace and all referenced records before revealing values. Recovery restores original comparison values and query, permits correction of incomplete input, and never submits automatically. Every recovery-capable sheet save/undo also carries the initiating user ID, checked against the current actor; every save still validates current values/revision. Existing callers without that new context field retain their API behavior. Lost responses can be confirmed without another write. Missing records block the entire candidate rather than exposing unvalidated content.

Clear sheet copies on explicit logout; invalidate mounted sheets on account/workspace changes and stop future writes from disposed/invalidated controllers. Returning to the original authorized workspace may recover its distinct copy. Discovered revocation clears that scope. Already transmitted requests may finish; no new writes start after departure or invalidation. Browser back/forward, navigation, reload and a new browser context using the same storage must recover through the same review. This is browser-local recovery, not cross-device sync or guaranteed survival when browser storage is removed. Undo receipts remain in the mounted session.

Acceptance: bounded/invalid/expired storage, independent writers, logout/epoch invalidation; native permission, stale-membership, foreign/missing-record and no-write checks for recovery; built-Worker typed/review recovery, invalid input correction, partial/lost responses, concurrent values, navigation/history/reload/new-context, logout/workspace changes/revocation, storage failures and desktop/mobile. Preserve unrelated route query counts and measure shared bundle impact. Follow the one Sol High review and at most one focused re-review policy. No migration, deployment, real import/outreach, paid auditing or video work.
