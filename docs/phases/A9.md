# A9 — Activate Client

## Objective

Wire Client, Services, Team, Onboarding, Invitation, and Activity into one coherent activation flow.

Read:

- `docs/PRODUCT_SPEC.md`
- `docs/DOMAIN_MODEL.md`

## Preconditions

Activation should validate at least:

- Client is in an activatable state
- required primary contact exists
- purchased Services are configured
- required Team assignment/setup exists where applicable

## Activation Effects

Conceptually:

Draft Client
→ validate
→ generate onboarding
→ create onboarding instance/items
→ move Client to Onboarding
→ prepare client portal access
→ create/send client invitation
→ record activity

Only create later-domain work if Release A configuration explicitly requires it.

Do not pre-build Projects.

## Idempotency

Activation must be idempotent.

Protect against:

- double-click
- browser retry
- email retry
- queue/retry duplication later

A failed external email send must not duplicate core business records.

## Activity

Record significant events such as:

- CLIENT_ACTIVATED
- ONBOARDING_STARTED
- CLIENT_INVITED

## Verification

- exactly one onboarding instance
- repeated activation attempt is safe
- merged onboarding requirements remain unique
- client lifecycle changes correctly
- invitation generated correctly
- activity recorded
- retry after email failure does not duplicate activation data
