# A7 — Services and Departments

## Objective

Allow one Client to hold multiple purchased services and scoped team assignments.

Read:

- `docs/PRODUCT_SPEC.md`
- `docs/DOMAIN_MODEL.md`

## Initial Departments

Seed:

- Social
- Ads
- Systems
- Operations

## Initial Service Types

Seed at least:

- Social Media Management
- Ads
- GHL
- Kajabi
- Content Calendar

Additional service types may be added only if clearly needed for Release A examples.

## Service Engagement

A Service Engagement is a purchased service for one Client.

Do not create multiple Client records for multiple services.

Useful fields:

- client
- service type
- status
- package name
- start date
- scope notes
- assignment/team

Possible states:

- Planned
- Onboarding
- Active
- Paused
- Completed
- Cancelled

## Assignment

Support assignment at:

- Client level
- Service Engagement level

Service-level assignment will later drive contractor scope.

Example:

Maria assigned to James + Social
does not imply access to James + GHL.

## Verification

- one Client can hold several services
- service lifecycle independent from Client lifecycle
- scoped assignment represented correctly
- no accidental service duplication unless intentionally supported
- department membership alone does not grant unrelated client-service scope
