## P0 contract

- Preserve existing Better Auth identity. An HttpOnly, same-site workspace selection cookie is only a selector: every request must resolve that exact user's active membership in that active workspace. Invalid/revoked selection fails closed. No email-based joins or fallback to another workspace after an explicit invalid selection. Switching uses a same-origin authenticated POST and a full document navigation to discard old workspace UI/cache.
- Workspace chooser lists only the signed-in user's active memberships. Owner/Admin in an active workspace may explicitly create one new empty Prospecting workspace per request ID. The atomic creation grants only the initiating existing identity an Owner membership. It creates no other user, credential, source mapping, mailbox, schedule or automation. Retry returns the same workspace and never reactivates revoked membership. Existing operational workspaces retain their default purpose.
- Prospecting workspaces have an explicit immutable purpose. Their owners cannot enter the inherited prospecting API/shell through the legacy compatibility adapter, preventing accidental access to old automation/settings. Original operational/legacy workspace selection and URLs keep working.
- P0 baseline uses the accepted built-Worker measurement wrapper, full destination completion plus two frames, separate request/query counts and bundle transfer. Compare Home, Clients and Work at 1440 and 390, with the same synthetic fixture and local D1 delay before/after. Record median/p95, samples and limitations. No global speed claim or resurrection of the closed performance project.

## P1 contract

- Routes: /prospecting (list/setup), /prospecting/new and /prospecting/:id. Contextual sidebar shows working Prospects navigation and Back to BloomOps only; main Pages remains in the main shell. The account menu exposes workspace selection with separately labelled identity/role/workspace. Clients never receive Prospecting navigation. Owner/Admin operate Prospecting in this slice; PM/Team/Client are denied server-side, including stale issued actors.
- Canonical prospect records use additive Drizzle tables in existing D1, with immutable workspace/id/creation receipt and workspace/actor FKs. The inherited slug-keyed prospect table remains unmodified and unread by this feature; legacy jobs cannot consume the new records. P2 will explicitly import selected raw values into this boundary. No duplicate mutable source of truth for any imported record is created now.
- Identity: person, business, website, platform, niche, services, public contact email, location/timezone. Assessment: Unknown/Strong/Hold/Skip, reason, observed facts, unknowns and proposed work. Fit remains separate from contact status. Unknowns stay null/unknown. HTTP(S) source/website links only; no server fetching.
- Per-field provenance records manual source, optional source URL, review status and checked time. Verification means a person checked the field/source, never delivery verification. Editing a field invalidates its prior check unless the new value is explicitly checked. Durable revision checks and atomic activity avoid lost updates/duplicate writes; field source is not copied from an unrelated field.
- Full-page profile presents Identity, Assessment, separate expandable Audit evidence, Outreach draft and Activity. P1 supports a manually editable subject/body draft reached by an in-page link; it never sends or marks contact. Audit evidence is manually editable: date, target URL, full report, tested interaction and limitations. The report is expandable; automated audit mapping is P2. Contact/schedule/reply/automation show honest absent/inactive states until P3. No guessed counters, analytics or inactive sidebar placeholders.
- Lists are scoped/searchable, bounded 50+overflow with explicit pagination and native GET filters under a focused disclosure. Detail/read/update queries prove current membership/workspace/purpose/role. All API input is allowlisted, validated and bounded; responses never expose legacy records/settings/credentials. Activity is bounded and based on canonical actor/time/actions.
- Reuse Bloom typography, components, tokens and 44px controls. No dot/pipe/slash metadata chains, cramped drawers, nested tabs or universal card grids. Distinct label/control/help spacing, readable long text, mobile field recomposition and visible keyboard focus.
