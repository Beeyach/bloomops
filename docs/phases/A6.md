# A6 — Clients

## Objective

Build the first real BloomOps business domain: Clients.

Read:

- `docs/PRODUCT_SPEC.md`
- `docs/DOMAIN_MODEL.md`

## Client List

Useful lifecycle filters:

- All
- Draft
- Onboarding
- Active
- Paused
- Completed
- Ended

Client row/card should support useful operational summary without overloading the screen.

## Create Client

Initial fields:

- client/company name
- primary contact name
- primary contact email
- website
- timezone
- start date
- internal owner

New Client starts as Draft.

Creating a Client must not automatically invite them.

## Client Detail

Canonical route:

`/clients/:id`

Release A tabs:

- Overview
- Services
- Onboarding
- Team
- Activity

Future tabs should not be fake placeholders inside the client detail unless needed for navigation consistency.

## Contacts

Support multiple client contacts.

One may be primary.

Portal user linkage is nullable until invitation acceptance.

## Lifecycle

Client status:
- Draft
- Onboarding
- Active
- Paused
- Completed
- Ended

Client health:
- On Track
- Needs Attention
- At Risk

Keep status and health separate.

Health may be manually managed in Release A.

## Activity

Significant Client mutations should create immutable Activity Events.

## Verification

- create client
- edit client
- contact management
- owner assignment
- status/health independence
- workspace isolation
- activity recording
- archive/restore behavior if implemented

If scope becomes too large, split implementation into client core and client detail/contact/team subphases, but do not widen beyond A6.
