## New bounded N3A decisions

- One report is for one existing Client and purchased Service engagement, one
  inclusive date range (YYYY-MM-DD, years 0100–9999), IANA timezone, one account,
  one channel and one campaign/content scope. Monthly periods are entered as their
  actual start/end dates; no aggregation, comparison or previous-period copying.
- Both templates version 1 are fixed server catalogues. Their identifiers and
  definitions are immutable; drafts pin the version. Client, Service and template
  are fixed after creation. Title, period, timezone, account/scope, commentary and
  observations remain editable with an expected revision. No provider compatibility
  is claimed. GHL channel is explicitly email or SMS; social channel is explicitly
  Facebook, Instagram, LinkedIn, TikTok, YouTube or Other. No name/slug eligibility
  inference: a manager selects the appropriate actual engagement and template.
- All entered observations are optional. Each has state value/missing/unavailable/
  not_tracked, a count, source note (up to 1000 characters), and optional collection
  instant. Counts are integers 0–1,000,000,000. Non-value states hold null, never 0.
  All numbers remain **manually entered, unverified**, even with a source note.
  A blank source is explicitly labelled. No attachments or external source fetches.
- Header identity, period/timezone and channel are required to save. Account/scope,
  metrics and commentary may be incomplete; preview marks missing context. Commentary
  is plain text up to 8000 characters. Unsupported fields and derived-value input
  are rejected. No HTML is stored or interpreted.

### Catalogue (all entered counts optional; template version 1)

| Template/key | Label and exact definition |
| --- | --- |
| ghl_campaign/sent | Sent messages: messages submitted in this report's channel, account, campaign and period; not recipient count |
| ghl_campaign/delivered | Delivered messages: the subset of those submitted messages recorded as delivered |
| ghl_campaign/failed | Failed messages: messages recorded as failed; source note must explain whether bounces are included; never added to delivered to infer sent |
| ghl_campaign/clicked | Messages with clicks: submitted messages with at least one recorded click, not total click events or unique people |
| ghl_campaign/replied | Messages with replies: submitted messages with at least one recorded reply |
| ghl_campaign/opt_outs | Opt-outs: source-recorded opt-out events in the scoped period; not inferred from replies |
| social/published | Published content: source-recorded posts/content published for this account/channel/period |
| social/views | Views: source-native view count; source note describes its definition; not reach |
| social/reach | Reach: source-native reach for the whole account/scope/period, never a sum of overlapping post reach |
| social/interactions | Interactions: source-native interaction count; definition recorded in source note; no inferred engagement rate |
| social/link_clicks | Link clicks: source-native click events, not unique people |
| social/followers_start | Followers at period start: account follower count at beginning of period |
| social/followers_end | Followers at period end: same-account follower count at end of period |

Derived (never persisted as authoritative input):
- ghl_campaign/delivery_rate: delivered / sent × 100 percent, exactly two decimal
  places, round half up using integer arithmetic. Requires both values, nonzero sent
  and nonblank account/scope. Delivered > sent rejects the save. Missing context,
  non-value input or zero denominator displays Not available. 0/positive is 0.00%.
- social/follower_change: followers_end − followers_start, signed integer people;
  requires both values and account/scope. No growth percentage. All derived output
  is labelled calculated from unverified manual inputs.
- No click/reply/engagement rate, unique cross-channel totals, revenue, leads,
  bookings or attribution calculation. These require separately defined sources.

The referenced HighLevel reports/email-widget articles were inspected for context;
these conservative manual definitions are N3A choices, not claims of exact provider
export semantics or automatic verification.

## Storage, consistency and authority

Use Drizzle/D1 relational client_report_drafts plus client_report_metrics. Reports
reference the actual (workspace, client, engagement) unique Service tuple, and
creator/updater identities and workspace memberships. Observations belong to the
same report/workspace. Composite FKs, unique report/metric identity, index for
bounded Client lists, mandatory values and immutable parent/template identity guards
apply. Generated additive migration; no publication infrastructure or old-row rewrite.
One guarded D1 batch saves header/observations atomically. Same creation UUID retries
return its original draft; changed intent conflicts. Updates use expected revision;
conflicts preserve input, never overwrite automatically. Failed/zero-row header writes
cannot replace observations. Reads and writes check current authority in SQL.

Read/preview: current active Owner/Admin/PM, or Team with a current Client-wide
assignment. Edit: Owner/Admin/PM (existing client.manage/service.manage roles).
Both Client and Service view permission are required; a Service-only assignment
cannot enter the internal Client surface. Canonical evaluate/loadInternal* helpers
and liveProjectActor supply the existing role, scope and identity rules. Preview
actors and Client memberships always deny. No new capability or portal grant.
Recheck reads, saves and preview; no cross-request cache or private browser storage.
Scope-bound requests include current user/workspace guards. Lists are 20/page with
permission filtering before the limit. Services are bounded with explicit search.

## Routes/UI

Internal Client Reports tab → /clients/:id/reports/new → saved report edit at
/clients/:id/reports/:reportId → /preview. API under /api/bloomops/clients/:id/reports
and /:reportId. Preview loads persisted data through the same authority and renders
in internal chrome, explicitly Private preview. It never publishes, grants portal
access or provides a public link. Forms retain input on validation/network/conflict
errors and warn before leaving unsaved work. Reopen current saved data explicitly
after conflict. No fake charts, publish/PDF controls or global navigation destination.
